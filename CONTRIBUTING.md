# Contributing to Clover UI

Thanks for wanting to help. Clover UI is a collection of motion-first React components you copy into your own project through a shadcn-compatible registry. Every contribution, from a typo fix to a brand new component, is welcome.

## Ways to contribute

- Report a bug or a rough edge in a component
- Improve the docs or the docs site itself
- Add a new component
- Polish an existing component (performance, accessibility, responsiveness)

If you plan something big, open an issue first so we can agree on the direction before you spend time on it.

## Getting started

You need Node.js 20+ and [pnpm](https://pnpm.io).

```bash
git clone https://github.com/purposewalks9/clover-ui.git
cd clover-ui
pnpm install
pnpm dev
```

The docs site runs at `http://localhost:3000`. Each component lives at `/components/<name>`.

Useful commands:

| Command | What it does |
| --- | --- |
| `pnpm dev` | Start the docs site in dev mode |
| `pnpm build` | Production build of the docs site |
| `pnpm lint` | Run ESLint |
| `pnpm registry:build` | Regenerate `public/r/*.json` from `registry.json` and the component sources |

## Project structure

```
app/                     Next.js app: routes, layout, global styles
components/              Docs site components (sidebar, header, playground, props table)
  playground/            Live prop editor: control panel, color picker, shell
  ui/                    Base primitives (sidebar, popover, sheet, etc.)
docs/<name>/             Docs for one component
  doc.mdx                Page content: playground, install, usage, props table
  demo.tsx               Static demo
  playground.tsx         Interactive playground wiring
registry/clover-ui/      The component source files users actually install
registry.json            Registry manifest: one entry per component
public/r/                Built registry output, generated by pnpm registry:build
lib/                     Helpers (config, registry access, playground code generation)
hooks/                   Shared React hooks
```

The docs sidebar builds itself from `registry.json` and the `docs/` folders, so there is no hand-maintained nav list.

## Adding a component

1. **Write the component** at `registry/clover-ui/<name>.tsx`.
   - File names are kebab-case, component names are PascalCase.
   - Start with `"use client"` when it uses hooks or motion.
   - Import `cn` from `@/lib/utils` and animate with `motion/react`.
   - Use `forwardRef` and expose `play` / `reset` handles when the component has an entrance animation, matching `drop-text` and `nucleus-text`.
   - Keep props optional with sensible defaults so `<YourComponent>hello</YourComponent>` just works.
2. **Add the docs** in `docs/<name>/`:
   - `demo.tsx` exports a `Demo` component.
   - `playground.tsx` builds a `PlaygroundShell` with a list of controls (`text`, `number`, `boolean`, `select`, `color`).
   - `doc.mdx` shows the playground, an `InstallationTabs` block, a usage snippet and a props table.
3. **Register it** by adding an entry to `registry.json`:
   ```json
   {
     "name": "your-component",
     "type": "registry:component",
     "title": "Your Component",
     "description": "One sentence on what it does.",
     "files": [
       { "path": "registry/clover-ui/your-component.tsx", "type": "registry:component" }
     ],
     "dependencies": ["motion"],
     "registryDependencies": [],
     "category": "text"
   }
   ```
4. **Build the registry** with `pnpm registry:build` and commit the updated `public/r/` files.
5. **Check it works**: run `pnpm dev`, open your component page, try every playground control, then resize the window down to a phone width.

## Renaming or removing a component

Do it everywhere in one pass: the source file, the `docs/<name>/` folder, the `registry.json` entry, then run `pnpm registry:build`. Delete the stale `public/r/<name>.json` by hand, because the build does not remove orphaned files. Finish with a repo-wide search for the old name.

## Code style

- TypeScript everywhere, no `any` unless there is no other option.
- Tailwind for styling. Prefer design tokens (`bg-background`, `text-muted-foreground`) over hard-coded colors in docs site code.
- Components should be responsive from 360px up and should respect `prefers-reduced-motion` where the motion is decorative.
- Keep the code self-explanatory. This repo does not use code comments, so lean on clear names and small functions instead.
- Run `pnpm lint` before pushing.

## Commit messages

We follow [Conventional Commits](https://www.conventionalcommits.org):

```
feat(nucleus-text): add particle count control
fix(sidebar): cover full screen on mobile
docs: add contributing guide
refactor(registry): rename candlestick chart file
chore: rebuild registry output
```

Types: `feat`, `fix`, `docs`, `refactor`, `perf`, `style`, `chore`.

## Pull requests

1. Fork the repo and create a branch: `git checkout -b feat/your-change`.
2. Keep the PR focused. One component or one fix per PR.
3. Make sure `pnpm lint` and `pnpm build` pass and `public/r/` is regenerated.
4. Describe what changed and why. Add a screenshot or short recording for anything visual.
5. Be open to feedback. Reviews are about making the component better, not about you.
