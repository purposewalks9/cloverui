# Contributing to Clover UI

Thank you for your interest in contributing to Clover UI! This guide walks you through the project layout and shows you, step by step, how to add a new component.

**Adding a component touches 5 files.** The sidebar, search, sitemap and share images all build themselves from the registry.

When you're done, open a pull request from your fork to the main repo [here](https://github.com/purposewalks9/cloverui/compare).

## Getting Started

### Fork and Clone the Repository

1. **Fork this repository**
   Click [here](https://github.com/purposewalks9/cloverui/fork) to fork the repository.

2. **Clone your fork to your local machine**

   ```bash
   git clone https://github.com/<YOUR_USERNAME>/cloverui.git
   ```

3. **Go to the project folder**

   ```bash
   cd cloverui
   ```

4. **Create a new branch for your changes**

   ```bash
   git checkout -b my-new-component
   ```

5. **Install dependencies** (Node.js 20+ and [pnpm](https://pnpm.io))

   ```bash
   pnpm i
   ```

6. **Run the project**

   ```bash
   pnpm dev
   ```

Open http://localhost:3000 to view the docs. Every page lives at `/docs/<name>`.

## Project Structure

```
registry/clover-ui/   The components people install, one file each
registry.json         One entry per component
public/r/             Generated by pnpm registry:build, never edited by hand
docs/<name>/          One docs page: doc.mdx, plus demo, playground and examples for components
app/                  Next.js routes
components/           The docs site's own UI
lib/                  Data loaders and helpers
hooks/                Shared React hooks
```

## Adding a New Component

The steps below add a component called `example-component`.

### 1. Create the Component

Create `registry/clover-ui/example-component.tsx`:

```tsx
"use client";

import * as React from "react";
import { cn } from "@/lib/utils";

export interface ExampleComponentProps extends React.ComponentProps<"div"> {
  glow?: boolean;
}

function ExampleComponent({ glow = true, className, children, ...props }: ExampleComponentProps) {
  return (
    <div
      className={cn("inline-flex items-center gap-2", glow && "drop-shadow-lg", className)}
      {...props}
    >
      {children}
    </div>
  );
}

export { ExampleComponent };
```

The file must work on its own. It may only import `@/lib/utils` and the packages you list in step 2.

### 2. Update the Registry

Add your component to the `items` array in `registry.json`:

```json
{
  "name": "example-component",
  "type": "registry:component",
  "title": "Example Component",
  "description": "One short sentence on what it does.",
  "files": [
    {
      "path": "registry/clover-ui/example-component.tsx",
      "type": "registry:component"
    }
  ],
  "dependencies": ["motion"],
  "registryDependencies": [],
  "category": "effect",
  "meta": {
    "addedAt": "2026-10-22"
  }
}
```

- `category` picks the sidebar group: `button`, `control`, `text`, `loader`, `cursor`, `effect`, `background`, `asset` or `block`.
- `meta.addedAt` is the release date. Keep it unchanged on later edits.
- Also add `https://cloverui.xyz/r/example-component.json` to the `registryDependencies` of the `all` item at the top, so `@clover-ui/all` installs it too.

### 3. Create the Demo and Playground

Create `docs/example-component/demo.tsx`:

```tsx
import { ExampleComponent } from "@/registry/clover-ui/example-component";

export function Demo() {
  return <ExampleComponent>Your content here</ExampleComponent>;
}
```

Create `docs/example-component/playground.tsx`. This powers the Customize panel at the top of the page:

```tsx
"use client";

import { ExampleComponent } from "@/registry/clover-ui/example-component";
import { PlaygroundShell } from "@/components/playground/playground-shell";
import { jsx, type ControlDef } from "@/lib/playground";

const controls: ControlDef[] = [{ type: "boolean", prop: "glow", label: "Glow" }];

const defaultProps = { glow: true };

export function ExampleComponentPlayground() {
  return (
    <PlaygroundShell
      controls={controls}
      defaultProps={defaultProps}
      code={(values) => jsx("ExampleComponent", { glow: values.glow }, "Your content here")}
      render={(values) => (
        <ExampleComponent glow={values.glow as boolean}>Your content here</ExampleComponent>
      )}
    />
  );
}
```

Controls can be `text`, `text-list`, `number`, `boolean`, `select`, `color` and `color-list`.

### 4. Write the Documentation

Create `docs/example-component/doc.mdx`:

<!-- prettier-ignore -->
````mdx
import { ExampleComponentPlayground } from "./playground"

<ExampleComponentPlayground />

## Installation

<InstallationTabs item="example-component">
```tsx file=../../registry/clover-ui/example-component.tsx
```
</InstallationTabs>

## Usage

```tsx
import { ExampleComponent } from "@/components/example-component";

<ExampleComponent>Your content here</ExampleComponent>
```

## Props

<PropsTable data={[
  { name: "glow", type: "boolean", default: "true", description: "Adds a soft shadow." },
  { name: "className", type: "string" },
]} />
````

Keep the writing short. The registry `description` already appears in the header, so the page doesn't repeat it.

### 5. Build the Registry

```bash
pnpm registry:build
```

This generates `public/r/example-component.json`, the file the shadcn CLI installs from.

### Adding Examples

To show variants such as colors or sizes, put them in `docs/example-component/examples.tsx`:

```tsx
"use client";

import { ExampleComponent } from "@/registry/clover-ui/example-component";

function ExampleComponentNoGlowExample() {
  return <ExampleComponent glow={false}>No glow</ExampleComponent>;
}

export { ExampleComponentNoGlowExample };
```

Then add an `## Examples` section between Installation and Usage. Give each example its own heading, at most one sentence, and a preview with its code:

<!-- prettier-ignore -->
````mdx
import { ExampleComponentNoGlowExample } from "./examples"

## Examples

### Without glow

<DemoCanvas>
<DemoPreview center className="min-h-64 md:min-h-72">
<ExampleComponentNoGlowExample />
</DemoPreview>
<DemoCode>
```tsx
<ExampleComponent glow={false}>No glow</ExampleComponent>
```
</DemoCode>
</DemoCanvas>
````

The Switch page (`docs/switch/`) is a full example.

## Component Guidelines

- Use TypeScript, with an exported `XProps` interface. No `any`.
- Write `function X(...)` and export it once at the bottom with `export { X }`. No default exports.
- Take `ref` as a normal prop (React 19). Don't use `forwardRef`.
- Use `import * as React from "react"` and the `@/` import alias.
- Style with Tailwind, put variants in `cva`, and merge classes with `cn()` from `@/lib/utils`. Accept `className` and spread `...props` onto the root element.
- Animate with `motion`. Respect `prefers-reduced-motion` with `useReducedMotion()`, and clean up timers, frames and listeners when the component unmounts.
- Work in light and dark mode, and at every width from 360px up.
- Don't write code comments. Clear names do that job here.

## Before Opening a Pull Request

Make sure all of these pass:

```bash
pnpm lint
pnpm exec tsc --noEmit
pnpm registry:check
pnpm test
pnpm build
```

`pnpm test` also runs property tests. They check that every component renders, then give the number-heavy components 100 random and extreme sets of props each, and check rules that must always hold, like "a slider value stays inside its range" or "nothing renders `NaN`". If one fails, it prints the input and a `PROPERTY_SEED`, so you can run the exact same case again with `PROPERTY_SEED=<seed> pnpm test`.

Then open your page, try every playground control, and shrink the window to phone width. Write the commit message as a short sentence, like `Add Example Component` or `Fix Switch focus ring`.

## How Pull Requests Get Merged

Small, focused pull requests get reviewed and merged fastest.

- Keep one change per pull request: one new component, or one fix.
- Say what changed and why in a few sentences. The pull request template walks you through it.
- Add a screenshot or short recording for anything visual, in light and dark mode.
- Don't change an existing component's look unless the pull request is about that. Fixes should leave its default appearance the same.
- Only commit the files your change needs. `public/r/` should only change through `pnpm registry:build`.

## Renaming or Removing a Component

Change everything in one pass: the component file, the `docs/<name>/` folder, the `registry.json` entry and its URL in the `all` item, and any home page card. Run `pnpm registry:build`, delete the old `public/r/<name>.json` by hand, then search the repo for the old name.
