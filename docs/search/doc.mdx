## Usage

A compact, borderless search trigger that opens a grouped command menu. The trigger uses your theme's background with a thin border, so it is white in light mode and black in dark mode. The wider modal uses your theme's surfaces, readable results, a compact input, and an integrated footer. Bring your own icons and item colors.

```tsx
"use client";

import { Search, type SearchGroup } from "@/components/search";

const groups: SearchGroup[] = [
  {
    id: "pages",
    label: "Pages",
    items: [
      { id: "/", label: "Home", category: "Pages" },
      { id: "/settings", label: "Settings", category: "Actions", keywords: ["preferences"] },
    ],
  },
];

export function SiteSearch() {
  return (
    <Search
      groups={groups}
      shortcut
      onSelect={(item) => window.location.assign(item.id)}
    />
  );
}
```

Filtering matches every word in the label, description, group label, category, or keywords. Category buttons are derived from your items. Give every group a unique `id`, and every item an `id` unique across all groups.

## Behavior

The input receives focus when the modal opens. Arrow Up and Arrow Down move through enabled results; Enter selects, and Escape closes. Focus stays inside the modal and returns to the trigger when it closes. On small screens the modal fits the viewport and its results scroll independently.

Set `shortcut` on **one** search per page to enable Command/Ctrl K and `/`. Shortcuts ignore text inputs and other dialogs. The trigger has no keyboard hint by default; pass `shortcutLabel` to opt into one. Item `shortcut` arrays are visual hints; your application owns those shortcuts. Disabled items cannot be selected.

`onSelect` receives the selected item, and an item's optional `onSelect` callback runs too. Use one callback style unless both actions are intentional. Selection closes the modal. The example playground only reports the selected action; it does not open apps or send mail.

Control the dialog with `open` and `onOpenChange`, or use `defaultOpen`. Pass a button as `trigger` to replace the default trigger. `trigger={null}` lets an external control open it; your application should restore focus to that external control after closing. `SearchTrigger` is also exported separately.

## Themes and installation

Requires React 19, Tailwind CSS v4, `@radix-ui/react-dialog`, `lucide-react`, and the standard shadcn `cn` utility. The registry declares its dependencies. No Next.js router, theme provider, docs imports, or external assets are required.

Colors come from the standard shadcn theme tokens: `background` for the trigger, `muted` for the modal frame, `popover` for the input and result cards, `accent` for the highlighted result, and `foreground`, `muted-foreground`, `border` and `ring` for text, borders and focus. It follows light, dark, and custom palettes automatically. Set your `.dark` class on `html` or `body`, since the dialog portals to `document.body`. The component inherits your font. No animation package is needed.
